## Deploy Vercel (mesma sessão)

- Sem `VERCEL_TOKEN` no ambiente: não é possível criar o projeto por API. Repo ficou
  pronto para import pelo dashboard (`apps/web` como Root Directory).
- `apps/web/vercel.json`: buildCommand `pnpm --filter @nextgen/db run build && pnpm run build`.
  `next build` cru falha (exit 127) porque `next` não está no PATH sem `pnpm run`.
- `binaryTargets = ["native", "rhel-openssl-3.0.x"]` é obrigatório; sem ele o deploy sobe e
  quebra em runtime.
- `/api/health` valida `assertRlsIsEnforced()`; testado com APP_DATABASE_URL apontando para
  o papel `postgres` (superusuário) → 503 `rls:false`. Caminho positivo → 200 `rls:true`.
- E-mail movido para `packages/auth/src/mail.ts` com export `@nextgen/auth/mail`: importar
  `@nextgen/auth` cria o PrismaClient no load (createAdminClient) e um health check não deve
  depender disso.
- Regra de segurança coberta por teste: `MAIL_TRANSPORT=console` é ignorado quando
  `VERCEL_ENV=production`.
