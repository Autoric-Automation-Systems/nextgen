## Prisma no bundle da Vercel (causa raiz de "site no ar mas db down")

Sintoma: landing/login 200, `/api/health` → `db: down`,
`PrismaClientInitializationError` sem código, mensagem
`could not locate the Query Engine for runtime "rhel-openssl-3.0.x"`, `latencyMs` baixo.

Causa: o output file tracing do Next **não seguiu o symlink do pnpm** até
`node_modules/.pnpm/@prisma+client@*/node_modules/.prisma/client`, então a lambda foi
publicada sem `libquery_engine-*.so.node`. `binaryTargets` e `serverExternalPackages`
já estavam corretos — não era isso.

Correção (`apps/web/next.config.ts`):
```ts
outputFileTracingIncludes: {
  "/**/*": [
    "../../node_modules/.pnpm/@prisma+client*/node_modules/.prisma/client/**/*",
    "../../node_modules/.prisma/client/**/*",
    "./node_modules/.prisma/client/**/*",
  ],
}
```

Verificação local sem deploy: buildar e conferir
`apps/web/.next/server/app/api/health/route.js.nft.json` — os dois engines
(`debian-openssl-3.0.x` e `rhel-openssl-3.0.x`) precisam estar em `files`.
